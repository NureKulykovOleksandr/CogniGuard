# CogniGuard — Система моніторингу когнітивного стану користувачів

**CogniGuard** — це комплексний програмний продукт, призначений для оцінки та моніторингу когнітивних функцій користувачів (реакції, робочої пам'яті тощо) за допомогою спеціалізованих тестів. Проєкт розроблено як клієнт-серверний застосунок з окремими веб- та мобільними інтерфейсами.

---

## 🏗️ Архітектура проєкту

Репозиторій містить три основні модулі:

1. **`backend/`** — серверний API на базі **Node.js (Express)** та **MongoDB (Mongoose)**. Надає функціонал авторизації, збереження результатів тестування, управління профілями та інтегрує документацію Swagger.
2. **`web/`** — веб-панель керування на базі **React (Vite)** для аналізу результатів та адміністрування.
3. **`mobile/`** — кросплатформний мобільний застосунок на базі **React Native (Expo)** для проходження тестів (PVT та N-back) користувачами, що має підтримку локального збереження результатів (через `AsyncStorage`) та синхронізації при відновленні з'єднання (Offline-first).

---

## 📱 Мобільний застосунок (`mobile`)

Мобільний застосунок розроблено на технологічному стеку **React Native** з використанням фреймворку **Expo**. 
Він є повноцінним мобільним застосунком, а не веб-сайтом. Застосування React Native дозволяє компілювати код у нативні компоненти iOS та Android.

### Основний функціонал:
* **Авторизація та профілі:** Реєстрація, вхід, збереження сесії та перегляд профілю користувача.
* **Тест PVT (Psychomotor Vigilance Task):** Оцінка швидкості реакції на випадкові візуальні стимули.
* **Тест N-Back:** Оцінка оперативної пам'яті та концентрації уваги.
* **Офлайн-режим (Offline-first):** Якщо з'єднання з інтернетом відсутнє, результати тестів зберігаються локально на пристрої та автоматично синхронізуються з сервером при наступному запуску застосунку з доступом до мережі.
* **Історія тестів:** Перегляд попередніх результатів користувача безпосередньо в застосунку.

## 🚀 Інструкція із запуску мобільного застосунку

Для запуску мобільної частини проєкту перейдіть у відповідну директорію:
```bash
cd mobile
```

### 1. Встановлення залежностей
Переконайтеся, що у вас встановлено Node.js, та виконайте команду:
```bash
npm install
```

### 2. Запуск через Expo Go (Найпростіший спосіб)
Цей спосіб дозволяє запустити застосунок на фізичному пристрої без необхідності налаштування Android SDK або Xcode:
1. Запустіть сервер розробки Expo:
   ```bash
   npx expo start
   ```
2. Встановіть застосунок **Expo Go** на свій смартфон (доступно в Google Play та App Store).
3. Відскануйте QR-код, який з'явився у консолі (для Android) або використовуйте вбудовану камеру (для iOS). Застосунок автоматично скомпілюється та запуститься на вашому телефоні.

### 3. Генерація нативного проєкту під Android/iOS (Prebuild)
Якщо викладач вимагає класичний нативний проєкт Android Studio (з файлами Gradle, Java/Kotlin кодом та нативною структурою):
1. Виконайте команду генерації:
   ```bash
   npx expo prebuild
   ```
2. Ця команда створить папку `android/` та `ios/` з усіма нативними конфігураціями. Після цього ви зможете відкрити папку `mobile/android` безпосередньо в **Android Studio**, скомпілювати її та запустити на емуляторі або зібрати APK-файл через Gradle.

### 4. Локальне збирання APK-файлу (Android)
Для збирання готового настановного пакета `.apk`:
* **Варіант А (локально через Gradle):**
  Після виконання `npx expo prebuild` перейдіть до папки `android` та виконайте команду збирання:
  ```bash
  cd android
  ./gradlew assembleRelease
  ```
  Готовий APK буде знаходитися за шляхом: `app/build/outputs/apk/release/app-release.apk`.
* **Варіант Б (через EAS CLI у хмарі Expo):**
  ```bash
  npm install -g eas-cli
  eas login
  eas build --platform android --profile preview
  ```
  Після завершення збирання у хмарі ви отримаєте посилання на завантаження готового APK-файлу.

## 🛠️ Налаштування підключення до API (Важливо для роботи на пристроях)

У сирцевому коді мобільного застосунку запити до сервера надіслано на адресу `http://localhost:3000`. При запуску на фізичному телефоні або емуляторі `localhost` посилається на сам телефон, тому запити не зможуть дійти до вашого комп'ютера.

### Як вирішити:
1. **Для Android емулятора:**
   Прокиньте порт з комп'ютера на емулятор за допомогою ADB:
   ```bash
   adb reverse tcp:3000 tcp:3000
   ```
2. **Для фізичного пристрою (через Wi-Fi):**
   Замініть `localhost` у файлах `App.js`, `LoginScreen.js`, `HistoryScreen.js`, `NBackTestScreen.js`, `ProfileScreen.js` та `TestScreen.js` на локальну IP-адресу вашого комп'ютера (наприклад, `http://192.168.1.100:3000`). Переконайтеся, що телефон та комп'ютер підключені до однієї мережі Wi-Fi.

## ⚙️ Запуск сервера та веб-версії

Для повноцінного тестування мобільного застосунку необхідно запустити бекенд:

### Запуск Бекенду (`backend`)
```bash
cd backend
npm install
npm start
```
*Бекенд автоматично підключається до хмарної бази даних MongoDB Atlas.*
*Документація API доступна за адресою: `http://localhost:3000/api-docs`.*

### Запуск Веб-інтерфейсу (`web`)
```bash
cd web
npm install
npm run dev
```
